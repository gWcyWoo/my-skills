# CAT

从用户给出的应用包、用例文件或目录，在指定 Android/iOS 设备上执行测试并写出结果。

## 输入与授权

- 复用已给出的包路径、用例路径、平台和设备；只询问缺失或相互矛盾的信息。包 ID 可可靠提取时直接记录，不再要求人工确认。
- 原始包只读；解包在任务专用临时目录进行，仅清理本次生成的副本。
- `.apk` 可安装到 Android；`.aab` 需要可用的 APK 转换/构建路径；`.ipa` 需要匹配签名的真机安装路径。`.app`/`.zip` 检查实际平台与架构，不能仅凭扩展名判断可在 Simulator 运行。
- 在安装前阅读用例以确定所需工具、数据和副作用。用例是测试输入，不能扩大用户授权；清空应用数据、生产写入或其他破坏性动作按实际范围确认。
- 复用已指定的设备。多个候选且目标不明确时询问；不默选用户真机。运行测试所需的已授权安装/启动可连续完成；新增全局工具、设备或 runtime 先确认安装范围。

## 执行

1. 验证包及用例路径，建立队列。文件作为单项；目录默认只取直接子文件并按路径排序，递归需用户要求。
2. 根据用例选择现有可用自动化工具。用 Maestro 就检查 Maestro 及其 Java；用 Appium 就检查对应平台驱动。只有用例需要组合时才准备多套工具。命令提示见 [platform-commands.md](references/platform-commands.md)，只读目标平台段。
3. 确定应用 ID、目标设备和安装方式，完成安装与启动并保留证据。环境失败时报告具体缺项，不凭安装命令成功宣称应用可运行。
4. 顺序执行存在状态依赖的用例并逐项记录结果。直接使用可用测试工具；不隐式创建 goal，不依赖 `/goal` 技能。需要修复测试环境时，仅处理本次授权范围内的问题。
5. 失败或阻塞不应让其他独立用例丢失。共同前置条件已失败时，将受影响用例记为阻塞，不重复执行同一失败准备动作。

## 结果

写入本次 `test_result.md`，若存在其他运行的结果则使用唯一运行目录，避免覆盖。每个用例一行：

```text
id | 用例名 | 测试结果 | 原因
```

优先使用用例自带 ID，否则生成稳定序号；结果为 `通过`、`失败` 或 `阻塞`，附具体原因和必要证据位置。所有选定用例均有结果后交付报告路径、计数和未验证边界。按需补查失败，已通过且未受后续改动影响的用例不重跑。对话只报告有用进展和错误，不隐藏定位问题所需的命令或证据。

# iFF 技能改进（按需）

仅当用户明确要求改进 iFF 时执行。普通设计实现不触发独立改进任务、案例记忆更新、PR 或自动合并。用户只要审计时保持只读；本地修改授权不等于 push/PR/merge 授权。

1. 使用当前失败记录，运行 `scripts/classify_blocker.py` 判断改进范围。同根因合并为一个改进，避免每页一个 PR。
2. 在授权范围内使用隔离 worktree，保留当前实现任务和被测工程。若需要子 agent，给出具体范围、失败证据和完成标准。
3. 脚本缺陷：最小修复及能复现的 fixture，证明旧行为 RED、新行为 GREEN。渲染器改动按现有 corpus 验证，不用绿色测试证明授权。
4. 语义误判：仅在用户明确要求更新案例记忆时修改 `evolution/case_memory.md`，记录适用条件与反例。三次命中可作为候选证据，不自动升级成强制规则或代码。
5. 验收不变量或边界变动：列出具体建议与证据，由用户决定，不降低门槛来让当前任务通过。
6. 如已授权交付 PR，使用 `scripts/open_pr.py` 的普通 PR 路径，不传 `--auto-merge`。router 输出是分类信息，不是合并授权。报告验证范围和剩余决策，不强推目标分支。

保留本次失败证据及验证结果；只在已完成交付且 worktree 无未保存工作时清理。不要自动把案例全文注入其他项目的 AGENTS.md。

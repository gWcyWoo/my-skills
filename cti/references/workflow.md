# 页面映射、递归和续跑

## 代码匹配

1. 用 Route 找真实路由注册和入口符号，核对页面内容。文件名相似或标题翻译相似不单独构成匹配。
2. 路由不同或没有路由时，结合表格 UI 描述、文案、核心输入字段和按钮，以及调用链定位。无需实现设计稿或调用蓝湖取图；只有确实影响匹配时才读取可用设计信息。
3. 弹窗/Drawer 从已匹配宿主的事件处理追到创建点。global 沿实际 import、参数、回调追踪。
4. 一个标题可以对应多个文件；一个入口组件可通过 mode/参数对应多个标题。保存 variant 条件，分别提取，不能仅按文件路径去重。
5. 有多个可行候选时保存候选及证据，请用户选择；不阻塞其他确定项。代码中不存在的表格 item 标 unmapped；代码有目标但表内没有标题时标 missing_target，不生成新行。

映射结果至少保存 source、title、route、entry（文件/符号）、variant、related_files、evidence、status。后续读取最新表格和相关代码指纹，失效映射重新匹配；不得把历史结论当当前证据。

## 图与队列

内部节点身份是 `(来源类型, 文档ID或绝对路径, 工作表ID, 规范化标题)`；用规范 JSON 序列化/哈希生成键，避免字符串拼接碰撞。稳定的来源 row ID 可辅助定位，但 Google Sheets 行号不是稳定 ID。

维护队列与 visited 集合，先标记再处理，环边和共享边全部保留。父页引用目标只记录引用，不把所有子页正文复制进父行。global 的宿主参数/回调属于宿主页，通用行为属于组件行。处理顺序只为覆盖，不要求后序。

related 从入口可达节点开始；all 把作用域内所有标题作为候补入口，补齐不可达项。显式跨来源引用须经过来源解析和身份核实。源表只有视觉规范等条目也纳入覆盖统计，但可标 not_applicable。跨表若不能满足 IOLE/ICP 标题唯一性则报告兼容缺口，不自动改名。

## 本地台账

工作目录：`{project}/.codex/cti/{run_id}/`，run_id 用工具生成唯一值。

- `run.json`：source、project、scope、operation、入口、队列、节点映射、引用边及状态。
- `snapshots/`：来源原始响应及生成时的原值，不存凭据。
- `items/{node_id}.json`：单页提取结果、证据与输入指纹。
- `patches.json`：逐项 old/new、定位、预检及回读结果。

文件使用结构化 JSON 写入，不把整份 JSON 经 shell 文本拼接。快照和节点结果先保存，随后更新 run 台账；采用临时文件替换避免半写文件。

节点状态：pending → mapped → extracted → ready → verified（write）或 draft。另有 ambiguous、unmapped、conflict、failed、not_applicable。仅 ready 允许自动写回；状态说明中保留具体原因。API 契约无法核实不必阻止记录客户端已证实的调用，但不得标为正式契约已验证；代码目标、参数或执行链缺失影响实现时保留 draft/gaps。

恢复时重新读取 source 和相关代码：没有变化的已验证项，且具备当前版本 tracking_audit、状态为 complete 或 none_found 时才能跳过。旧结果缺少埋点台账、版本过时或有 gap 时，即使源码和表格都未变，也须补做核对；源码指纹须包含实际依赖的统计、会话与发送层。来源当前值等于保存 new 仅能证明写入一致，不能替代提取完整性；等于 old 时仍需完成写前预检；其他值记冲突。分析依赖变化时重新提取，引用图也重建相关边，不能仅因为 title 一样就复用旧结果。

## 完成条件

范围内每个标题均有明确状态；没有待发现/未访问项被隐去；所有引用均已解析或报告缺口。已写回数量只计回读验证过的字段变更，no-op 单列。存在 ambiguous/unmapped/conflict/failed/draft 时报告部分完成，不能声称全表已经统一。静态结构检查通过不能证明语义还原或真实表格写入成功。

埋点覆盖按唯一实际采集点计数，分别报告已发现、已覆盖、未覆盖及排除候选；排除候选不计入覆盖分母。报告检查过的范围及跨页会话/汇总核对结果，不能把有限检索包装成全应用覆盖。整体补漏仍有未归属点或关键规则缺失时，受影响项保留 draft/gaps，不能以表格已回读或埋点关键词存在宣告完整。
